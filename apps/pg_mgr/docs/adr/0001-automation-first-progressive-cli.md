# Adopt an automation-first progressive CLI

`pg_mgr` will execute deterministically when sufficient arguments are supplied and will enter a guided flow only when required information is missing in an interactive terminal. This preserves a friendly experience for administrators while keeping commands predictable for scripts and operations platforms; non-interactive execution must never wait for input, and destructive actions require an explicit confirmation mechanism.

Identity and credential inputs, including the instance name and initial database password, must be supplied explicitly in non-interactive execution; the CLI must not silently use a fixed default identity or password. Values that can be safely derived, such as the newest compatible installed version and an instance data directory derived from its name, may default automatically. Routine configuration such as the port and database or operating-system user may retain documented defaults after validation. In an interactive terminal, missing required values are prompted for; outside a terminal, they produce an error naming the missing flags. Secrets should be accepted through mechanisms that avoid shell history and process arguments.

Whenever the possible answers form a closed set—including yes/no decisions and instance, version, or mode selection—the interactive CLI uses a numbered menu instead of free-form text. Destructive operations first display the exact affected resources and paths, then present a numbered yes/no choice that defaults to no; they do not require retyping a resource identifier. Invalid selections are explained and prompted again, while cancellation is reported explicitly. Non-interactive destructive execution requires an explicit target and `--yes`.

Multi-field operations that change system state, such as deployment, instance creation or adoption, upgrades, and backup configuration, display a review screen before execution. From that screen users can execute, choose a specific field to edit, or cancel without restarting the whole wizard; secret values are redacted and automatically derived values are identified. Single-action commands remain direct, and complete non-interactive invocations do not show a review screen apart from any required destructive-operation safeguard.

Each invocation presents user-interface text in exactly one language, selected from the process locale and overridable with a global `--lang` option. Prompts, validation messages, warnings, progress, results, and table headings are localized rather than hard-coded or shown bilingually. Command names, flags, and machine-readable field names remain stable English identifiers; diagnostics emitted by external tools retain their original text but receive a localized explanation.

Human-readable output defaults to localized tables or summaries, while query commands also support stable `table` and `json` output modes. Normal results are written to standard output; prompts, warnings, progress, and errors are written to standard error. JSON output contains stable English field names and automatically disables interaction, color, and dynamic progress. Color is terminal-aware and globally configurable, and quiet mode suppresses nonessential success presentation without hiding failures.

Exit status `0` means success or an explicit menu cancellation before side effects, `1` an execution failure, `2` invalid usage or input, `3` insufficient permission, `4` a missing or conflicting resource, and `130` interruption with Ctrl+C. Commands return categorized errors to a single root-level renderer instead of printing an error and exiting internally. A cancellation or failure after partial execution is nonzero and reports completed work, incomplete work, and recovery guidance; JSON errors are emitted to standard error with stable `code`, `message`, and optional `details` fields.

Long-running operations use consistent stages whose states are pending, running, completed, failed, rolled back, or skipped. Terminals may update these states dynamically, while non-terminal execution emits durable line-oriented events. A failure stops dependent stages and summarizes completed work, recovery performed, retained state, and concrete next steps. Safe rollback is automatic, but data that cannot be safely reconstructed is retained by default. Underlying commands and full external diagnostics are reserved for verbose mode, and secrets are redacted at every verbosity level.

Wizard fields are validated immediately and only an invalid field is repeated. Numbered menus reserve `0` for cancellation, multi-step wizards also accept `b` to return one step, and free-text fields treat those characters as ordinary values. The final review screen allows any field to be edited. Changes that invalidate derived or dependent values are disclosed and reconfirmed rather than silently propagated. Password steps offer only retaining the already-set secret or replacing it, and end-of-input cancels safely instead of accepting a dangerous default.

Required privileges are checked before business input is collected or side effects begin. If the current identity is insufficient, the CLI exits with a copyable retry command and an explanation of the permitted identities; it never reads or forwards sudo or `su` credentials and never introduces an elevation prompt partway through execution. Machine-readable mode reports the same permission failure and remediation without attempting elevation.

The explicit `--non-interactive` option disables all prompting, while `--yes` alone grants confirmation for guarded operations. The legacy `--silent` option remains for one release as a deprecated alias of `--non-interactive` and never implies `--yes`; the fixed default password is removed immediately. The implicit default instance name survives only for legacy `--silent` calls during that period and emits a warning. Legacy command aliases remain available, but help and documentation present only canonical commands.

Terminal presentation is restrained and operational: a small stable symbol set accompanies textual status labels, and color reinforces rather than carries meaning. Semantic colors are limited to success, warning, error, and guidance; ordinary values remain uncolored. Narrow terminals switch wide tables to record-style details, non-terminal or color-disabled environments use plain text, and indeterminate animation is used only for genuinely indeterminate waits. Output avoids decorative borders, fabricated percentages, and unnecessary vertical whitespace.

Resource-group commands without a subcommand display concise help and examples rather than running an implicit default action. Progressive prompting occurs only at leaf commands that lack a required target, and only in an interactive terminal; non-terminal and JSON invocations fail with an actionable missing-argument error. Primary help presents canonical commands, leaving legacy aliases to compatibility documentation.
